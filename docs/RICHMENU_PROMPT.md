# リッチメニューを確実に作るためのプロンプト

リッチメニューは**作り方を知らないとほぼ必ず失敗する**部類のもの。
失敗しても登録は通ってしまい、「押しても何も起きないメニュー」が出来上がる。
このプロンプトは、その落とし穴を全部潰した手順になっている。

**このリポジトリでは既に完成している**（`tools/richmenu/` と `bin/richmenu/*.png`）。
作り直したいとき、別案件で作るとき、中身を変えるときにこれを読む。

---

## なぜ失敗するのか（先に読む）

リッチメニューは**2つの別々のもの**で出来ている。

1. **画像**（2500 × 1686 のPNG）— 見た目
2. **当たり判定**（`areas` のJSON）— どこを押すと何が起きるか

**LINE側はこの2つが一致しているか検査しない。**
絵のボタンが当たり判定から10pxずれていても、登録は成功する。
そして押すと隣のボタンが反応するか、何も起きない。

さらに詰まりやすいのが次の4つ。

| 症状 | 原因 |
|---|---|
| 登録時に弾かれる | 画像が 2500×1686 ちょうどでない／1MBを超えた |
| 文字が □□□ になる | 日本語フォントが描画に間に合っていない |
| 絵がぼやける／2倍サイズになる | スクリーンショットの倍率が1になっていない |
| ボタンがずれる | CSS grid の `gap` や `border` の丸め誤差が積み上がった |

---

## プロンプト本文（ここから下をコピー）

LINE公式アカウントのリッチメニュー画像を作る道具を実装してください。

### 前提

- リッチメニューは3タブ（車を探す／車を売る／サポート）。タブごとに1枚、計3枚
- 当たり判定は `src/RichMenuDefinition.php` に既にある。**これが唯一の正**
- 画像は `bin/richmenu/{find,sell,support}.png` に出す
- 登録スクリプト `bin/setup_richmenu.php` は既にあり、このファイル名を見ている

### 満たすこと

**1. 当たり判定と絵を、同じ数値から描く**

座標を自分で書き写さない。`RichMenuDefinition::all()` をPHPで実行して
JSONで受け取り、その `bounds`（x, y, width, height）の数値でそのまま絵を描く。

```
php -r 'require "config/config.php"; echo json_encode(App\RichMenuDefinition::all());'
```

こうすれば、あとで座標を変えても絵が自動で追従し、ずれようがない。

**2. セルは絶対座標で置く。grid の gap を使わない**

`display:grid` + `gap` や `border` は小数の丸めで1pxずつずれることがあり、
6枚のセルが少しずつ当たり判定からはみ出す。
`position:absolute; left:<x>px; top:<y>px; width:<w>px; height:<h>px` で置く。

見た目の余白は、セルの**内側**に padding として取る
（当たり判定はセル全体のままにしておく。境目を押しても必ずどれかが反応する）。

**3. 日本語フォントは埋め込む**

`<link>` でGoogle Fontsを読ませると、**描画の瞬間にまだ落ちてきておらず
豆腐（□）のまま撮れる**ことがある。しかも毎回ではなく時々起きるので気づきにくい。

フォントのTTFを一度ダウンロードして保存し、base64で `@font-face` に
埋め込んでからレンダリングする。撮る直前に `document.fonts.ready` を待つ。
ダウンロードできない環境では、システムのゴシック体に落として警告を出す。

**4. 倍率は必ず1**

ヘッドレスブラウザのスクリーンショットは、既定で端末の倍率がかかることがある。
`deviceScaleFactor: 1` を明示する。2だと 5000×3372 になり、LINEに弾かれる。

**5. 出来た画像を機械で検査する**

人が見て「だいたい合ってる」で済ませない。生成のたびに次を確かめ、
1つでも外れたら異常終了する。

- PNGのヘッダ（IHDR）から読んだ幅と高さが **2500 × 1686 ちょうど**
- ファイルサイズが **1MB以下**

**6. 当たり判定を重ねた確認用画像を出せるようにする**

`--overlay` のようなオプションで、`areas` の矩形を赤い破線で重ねた画像を出す。
**白いカードが枠の内側に収まっていること**を目で確かめられるようにする。
この確認用画像はコミットしない。

**7. 絵の中の日本語ラベルを二重管理しない**

ラベルは `RichMenuDefinition` の `action.label` から読む。
絵に書いた文言と、押したときトークに出る文言（`displayText`）がずれると、
お客様には「押したボタンと違うものが出た」ように見える。

長い文言は字を詰める（文字数で font-size を落とす）。
折り返すと行が増えてセルから溢れるので、`white-space: nowrap` にする。

### 絵の中身

3タブ共通の構造:

```
上段（高さ 346px）  タブ3つ。選択中は濃い色、非選択は #DFDCD4 で少し下げる
下段（高さ 1340px） 3列 × 2行の6ボタン。白いカードに
                    アイコン（約190px）／ 日本語ラベル（50〜62px）／ 英字（30px）
```

配色はタブごとに変える。

| タブ | 背景 | 英字・副題 |
|---|---|---|
| 車を探す | `#4FA3F0` | `#1268C4` |
| 車を売る | `#FF8A2B` | `#C85A0E` |
| サポート | `#2FC4D6` | `#0B7F91` |

白いカードは `border: 9px solid #22262D`、`border-radius: 52px`、
`box-shadow: 0 13px 0 rgba(21,27,43,.34)`（下辺の影で押せることを示す）。

**アイコンは線画だけにしない。** 色面で描いたイラスト調にする。
リッチメニューは小さく表示されるので、線だけだと何のボタンか判別できない。

### 完成の確認

```bash
node tools/richmenu/build.mjs
#   [OK] find.png  2500x1686  153KB
#   [OK] sell.png  2500x1686  150KB
#   [OK] support.png  2500x1686  148KB

node tools/richmenu/build.mjs --overlay   # 赤枠の内側に収まっているか目視
php bin/setup_richmenu.php                # 登録内容の確認（まだ登録しない）
php bin/setup_richmenu.php --apply        # 登録
```

### 動かす場所

**これは開発機で使う道具。** 出来たPNGだけをサーバーに置けばよく、
Node.jsもヘッドレスブラウザもサーバーには要らない
（エックスサーバーの共用サーバーには入れられない）。

## LINE側の制限（調べ直さなくていいように）

| 項目 | 値 |
|---|---|
| 画像サイズ | 2500×1686 / 2500×843 / 1200×810 / 1200×405 / 800×540 / 800×270 |
| 形式 | JPEG または PNG |
| ファイルサイズ | 1MB以下 |
| 当たり判定の数 | 20個まで |
| `label` の長さ | 20文字まで |
| `chatBarText` | 14文字まで |
| エイリアスID | 半角英数字とハイフン、32文字まで |

タブ切替は `richmenuswitch` アクションとエイリアスで行う。
**エイリアスを先に作っておかないと、切替先が無いメニューになる。**
登録の順番は「メニューを作る → 画像を上げる → エイリアスを張る」。

タブ切替も postback として飛んでくる。**返信してはいけない**
（押すたびにトークが埋まる）。このリポジトリでは `tab=` を見て無視している。
