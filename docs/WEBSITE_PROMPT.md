# AUTOBEST コーポレートサイト 全面リニューアル — 実装プロンプト

Codex などの実装担当に渡すための仕様。画像の生成も含めて依頼できる形で書いてある。

**LINE公式アカウント（`rmatsu911/autobest-line-bot`）と同じブランドとして成立させる**のが前提。
配色・言い回し・導線をそちらと揃える。バラバラだと「別の会社」に見える。

---

## はじめに：この案件で一番まずいこと

中古車販売は**景品表示法と古物営業法が効く業種**。
サイトに書いた数字や写真が実態と違うと、行政指導の対象になる。

だから実装担当への指示として、最初に次を置く。

> **分からないことを埋めない。** 創業年・実績台数・スタッフ数・許可番号・
> 在庫の写真・お客様の声。これらは**取材して実物をもらうまで `[ ]` のまま残す**。
> それらしい数字を入れない。それらしい写真を生成しない。

「100万円のサイト」と「100万円に見えるサイト」の差はここに出る。
中身が空のまま見栄えだけ作ると、公開できないものが出来上がる。

## プロンプト本文（ここから下をコピー）

中古車の買取・販売店「AUTOBEST」（autobest.jp）のコーポレートサイトを
全面リニューアルしてください。静的サイトとして作り、エックスサーバーに置きます。

### 0. 守ること

1. **事実でないことを書かない。** 下の「取材シート」で `[ ]` になっている項目は、
   埋まるまで `[創業年]` のように角括弧のまま残すこと。
   もっともらしい数字・体験談・許可番号を発明しない
2. **在庫車両・店舗・スタッフの写真は生成しない。** 実写が届くまでは
   プレースホルダー（グレーの枠に「写真差し替え」）にする。理由は下の「画像」節
3. **古物商許可番号の表示欄を必ず作る。** 古物営業法で表示義務がある
4. 価格表示は総額表示。「支払総額」と「車両本体価格」を必ず並べる

### 1. この会社について（分かっていること）

- 中古車の**買取と販売**の両方を行う
- 拠点は**福岡本社**と**神奈川支店**の2つ
- 扱う区分は4つ：**乗用車・軽／トラック・バス／重機・作業車／その他車両**
- **LINE公式アカウントが稼働中**。在庫検索・無料査定・来店予約がLINEで完結する
- 買取の訴求は「高額査定」。実績と理由をページとして持つ想定

### 2. 打ち出す強み

次の4つを軸に構成する。**1番が最大の差別化**。

1. **乗用車から重機まで、一社で引き取れる**
   普通の中古車店はトラックや重機を断る。フォークリフト、ユンボ、ダンプまで
   扱えるのは同業でも少ない。「他店で断られた」層をここで取る
2. **福岡と神奈川の2拠点**。西日本と関東の両方に接点がある
3. **LINEで完結する。** 査定の申込も来店予約も、アプリを入れずLINEだけで終わる。
   電話が苦手な層・日中に電話できない職人層に効く
4. **高額査定**。ただし**「なぜ高く買えるのか」の理由は取材して埋める**
   （販路・整備・在庫回転のどれか。書けないなら4番は前面に出さない）

### 3. 取材シート（埋まるまで `[ ]` のまま）

実装前に店側へ確認する項目。**勝手に埋めない。**

```
会社
  [ ] 正式な法人名／屋号
  [ ] 創業年・設立年
  [ ] 代表者名
  [ ] 古物商許可番号（公安委員会名を含む）  ← 表示義務
  [ ] 適格請求書発行事業者の登録番号（あれば）
  [ ] 資本金・従業員数（出すなら）

拠点（福岡本社／神奈川支店それぞれ）
  [ ] 住所（郵便番号から）
  [ ] 電話番号・FAX
  [ ] 営業時間・定休日
  [ ] 駐車場の有無、最寄り駅からの道順
  [ ] Googleマップの埋め込みURL

強み（ここが一番大事）
  [ ] なぜ他店より高く買えるのか。販路は？（輸出／業者オークション／自社販売）
  [ ] 年間の買取台数・販売台数
  [ ] 重機やトラックを扱えるようになった経緯
  [ ] 整備や板金は自社か外注か。認証工場の有無

証拠
  [ ] 買取実績（車種・年式・金額・時期）。最低12件
  [ ] お客様の声（本人の許可が取れたものだけ）
  [ ] スタッフの写真と一言
  [ ] 店舗の外観・内観・整備場の写真
  [ ] 受賞歴・加盟団体（JU、AIS、JAAIなど）

その他
  [ ] 対応エリア（出張査定はどこまで行くか）
  [ ] 保証内容（販売時の保証期間）
  [ ] ローンの取扱い（提携信販会社）
  [ ] 現在のサイトのURL（引き継ぐ内容・残すURLの確認）
```

### 4. 訪問者の3タイプと、最初の1画面

ファーストビューで**必ず3方向に分岐させる**。中古車サイトは
「売りたい人」と「買いたい人」が混ざると、どちらも迷って離脱する。

| 誰 | 探しているもの | 置くボタン |
|---|---|---|
| 売りたい人 | いくらになるか | **無料査定を申し込む**（一番大きく） |
| 買いたい人 | 在庫と値段 | **在庫を見る** |
| 業者・大型車を持つ人 | 断られない店か | **トラック・重機の買取** |

さらに全ページ共通で**LINEへの導線**を固定表示する
（スマホは下部固定バー、PCは右下に浮かせる）。

### 5. ページ構成

```
/                       トップ
/purchase/              買取（査定申込までの一本道）
/purchase/truck/        トラック・バスの買取     ← 検索流入の主力
/purchase/machinery/    重機・建機・フォークリフトの買取 ← 同上
/purchase/flow/         買取の流れ
/purchase/documents/    必要書類
/purchase/results/      買取実績（一覧・絞り込み）
/stock/                 販売在庫（一覧）
/stock/<id>/            車両詳細
/about/                 会社概要（許可番号・沿革・代表挨拶）
/stores/fukuoka/        福岡本社
/stores/kanagawa/       神奈川支店
/staff/                 スタッフ紹介
/voice/                 お客様の声
/faq/                   よくある質問
/contact/               問い合わせ
/privacy/               プライバシーポリシー
/terms/                 サイトのご利用について
```

**`/purchase/truck/` と `/purchase/machinery/` を独立ページにするのが要。**
「福岡 トラック 買取」「ユンボ 売却」で検索する人は、
乗用車の話が混ざったページには留まらない。

### 6. 各ページの中身

**トップ**

```
1  ヒーロー：一言のコピー ＋ 3分岐ボタン ＋ 信頼の数字（取材後に埋める）
2  3行の要点：何でも買い取る／2拠点／LINEで完結
3  取扱区分4つ（乗用車・軽／トラック・バス／重機・作業車／その他）を
   カードで。各カードから買取ページへ
4  買取実績（直近6件をカルーセル。金額を大きく）
5  「なぜ高く買えるのか」3ステップ ← 取材後に埋める
6  査定の流れ（4ステップ、所要時間を明記）
7  販売在庫（新着6台）
8  お客様の声 3件
9  2拠点の地図とアクセス
10 LINEの案内（友だち追加のQRと、できることの説明）
11 よくある質問 上位5件
12 最後にもう一度、査定申込のボタン
```

**買取ページ（`/purchase/`）**

査定申込フォームまでの一本道にする。途中で他ページへ逃がさない。

- 冒頭に「30秒で申込完了」と所要時間を明示
- 他社と比較されることを前提に、**断らない車種**を具体的に列挙
  （10万km超／不動車／事故車／車検切れ／ローン残債あり／重機・農機）
- 実績を金額つきで見せる
- フォームは**項目を絞る**（名前・電話・メーカー・車種のみ必須）。
  年式や走行距離まで必須にすると、うろ覚えの人がそこで離脱する
- LINEで申し込む選択肢を必ず並べて置く

**在庫一覧（`/stock/`）**

- 絞り込み：区分・拠点・価格帯・年式・走行距離
- カードに 写真／車名／年式・走行距離／**支払総額**／拠点／新着バッジ
- 重機は走行距離ではなく**稼働時間（h）**を出す
- 価格未定の車両は「価格応談」と出す（0円や空欄にしない）
- **1台も無いときに空白のページを出さない。** 「入荷のお知らせをLINEで受け取る」を出す

**会社概要**

古物商許可番号、法人名、代表者、所在地、電話、設立年を表形式で。
ここが薄いサイトは業者に信用されない。

### 7. デザイン

**LINE公式アカウントと同じ配色を使う。** 別物にしない。

```
主色（買う・探す系）   #1268C4   面で使うなら #4FA3F0
副色（売る・査定系）   #E2600A   面で使うなら #FF8A2B
補助（サポート系）     #0B8FA3   面で使うなら #2FC4D6
濃紺（見出し・ヘッダ） #1F3358 ／ 文字 #16283F #22262D
補助文字               #5A5F68
アイボリー（地）       #FDFAF3
罫線                   #EAE4D6
強調・新着             #FFB020
価格                   #C85A0E
注意・赤               #F0525A
```

**査定（売る）はオレンジ、在庫（買う）はブルー**で一貫させる。
ページを開いた瞬間に「いま自分はどちら側にいるか」が色で分かる状態にする。

- 日本語書体は Noto Sans JP。見出し 700〜900、本文 400〜500
- 本文は16px以上、行間1.8。**主な閲覧者に年配の方と職人層がいる**
- 角丸はやや大きめ（12〜20px）。ボタンは下辺の影で押せることを示す
- 写真は明るく、影は浅く。暗い高級車サイト風にしない（対象層が違う）
- アニメーションは**スクロールで軽くフェードイン**する程度。
  派手な視差効果は入れない（スマホで重くなり、離脱に直結する）

### 8. 画像

**生成してよいもの**

- 抽象的な背景（幾何パターン、グラデーション、質感）
- アイコン、イラスト（車種の区分を示す図など）
- 図解（買取の流れ、査定の仕組み）
- 地図を簡略化したイラスト

**生成してはいけないもの**

- **在庫車両の写真。** 生成画像を実在の在庫として出すのは不当表示
- **店舗・整備場の外観内観。** 行ったら違う建物、は信用を失う
- **スタッフの顔。** 実在しない人物を社員として出さない
- **お客様の声に添える顔写真。** 同上

実写が届くまでは、グレーの枠に「写真差し替え」と入れたプレースホルダーを置き、
**差し替えが必要な箇所の一覧を `docs/PHOTO_LIST.md` に書き出す**こと。

**生成する画像の指示（例）**

```
ヒーロー背景
  日本の地方都市の朝、舗装された広い展示場に朝日が差している様子を
  抽象化したグラフィック。写実的な車は描かない。
  空の青（#4FA3F0）から暖かい砂色（#FDFAF3）へのグラデーション。
  横長 2400x1200、上下に文字を載せる余白を取る。

取扱区分のアイコン 4種
  乗用車／トラック／油圧ショベル／フォークリフト。
  色面で描いたフラットイラスト。線画だけにしない。
  正方形 512x512、背景は透明。主色 #1268C4、濃紺 #1F3358 のアクセント。
  4つ並べたときに大きさと重心が揃って見えること。

買取の流れの図解
  申込 → 査定 → 金額提示 → 成約・入金 の4ステップを横一列に。
  各ステップに所要時間を入れられる余白を作る。
  オレンジ #E2600A を進行方向に使う。横長 1600x400。
```

画像は WebP を第一に、JPEG/PNG をフォールバックに置く。
すべて明示的に `width` `height` を書く（レイアウトのガタつきを防ぐ）。
ヒーロー以外は `loading="lazy"`。

### 9. 技術要件

**作り方**

- 素のHTML / CSS / JavaScript。フレームワークを使わない
  （エックスサーバーの共用サーバーに置く。ビルド不要で更新できる形にする）
- CSSは1ファイルにまとめ、色・余白・文字サイズはカスタムプロパティで定義する
- JavaScriptは最小限。JSが動かなくても**内容が読め、電話がかけられる**こと

**速度**

- Lighthouse のモバイルで **性能90以上**
- LCP 2.5秒以内、CLS 0.1未満
- ヒーロー画像は `preload`。それ以外は遅延読み込み
- Webフォントは表示に必要な字だけをサブセット化する
  （Noto Sans JP のフルセットは重すぎる）

**SEO**

- 1ページ1テーマ。`title` と `h1` を狙う語に合わせる
  （例：「トラック買取 福岡｜10万km超・不動車も｜AUTOBEST」）
- 構造化データ（JSON-LD）
  - 全ページ `LocalBusiness`（拠点ごとに `AutoDealer`）
  - 在庫詳細 `Vehicle` + `Offer`
  - FAQページ `FAQPage`
  - パンくず `BreadcrumbList`
- `sitemap.xml` と `robots.txt`
- OGP と Twitter Card を全ページに
- **現在のサイトのURLを引き継ぐ場合は301リダイレクトの一覧を作る**

**アクセシビリティ**

- 文字と背景のコントラストは 4.5:1 以上
- すべての画像に `alt`。装飾画像は `alt=""`
- キーボードだけで申込フォームまで到達できる
- フォームの入力欄は16px以上（iOSの自動ズームを防ぐ）

**フォーム**

- 送信先は要相談。既存のLINE botに `public/assessment.php` があるので、
  **同じ入力規則・同じ迷惑送信対策を流用できる**
  （ハニーポット／経過時間／連投制限の3枚重ね。CAPTCHAは入れない）
- 送信後は必ずリダイレクトする（再読み込みでの二重送信を防ぐ）

### 10. LINEとの連携

既にbotがあるので、サイトはその入口として働かせる。

- 全ページ共通の固定バーに「LINEで査定」
- 友だち追加QRを、トップ・買取・各店舗ページに置く
- 在庫詳細から「この車をLINEで問い合わせる」
- 友だち追加リンクに流入元を付け、どのページから来たか分かるようにする

### 11. 在庫データの扱い（実装前に確認すること）

**この点だけは勝手に決めないこと。** 選択肢は2つ。

**案A：サイトは静的、在庫は手で更新**
LINE botの管理画面で在庫を管理し、サイトには主要な数台だけを手で載せる。
実装は軽いが、二重管理になる。

**案B：LINE botの在庫DBをサイトからも読む（推奨）**
botの管理画面で登録した在庫が、そのままサイトにも出る。
入力は1回で済む。`public/api/stock.json` のような読み取り専用の口を
bot側に作り、サイトはそれを読む。

**推奨は案B。** ただし現在のbotは「在庫は管理画面に手入力・DBは分離」という
前提で作られているので、**先に店側の合意を取ってから着手する**こと。

## 渡し方

このまま渡すと大きすぎるので、次の順で分けて依頼するとよい。

1. **取材シートを埋める**（実装担当ではなく店側の作業）
2. デザインと共通部品（ヘッダ・フッタ・CSS変数・画像生成）
3. トップページ
4. 買取まわり（`/purchase/` 一式）
5. 在庫まわり（案A/Bを決めてから）
6. 会社概要・店舗・FAQ・問い合わせ
7. 速度とSEOの仕上げ

3以降は、2で出来た共通部品の上に積む形になる。
